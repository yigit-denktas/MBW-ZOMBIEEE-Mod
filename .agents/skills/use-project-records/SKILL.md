# Use project records

Read local AGENTS instructions. Locate the declared manifest, pinned toolkit, source/field authority, overview, discovery coverage and installation/operation receipts.

For new setup, existing adaptation or readiness reassessment, read [the readiness contract](references/readiness-contract.md) and use [its empty assessment record](references/readiness-assessment.json). Record evidence-backed L0–L5 readiness separately from completion and R0–R4 task risk. Link the configured central assessment; preserve existing authorization and mark proposed autonomy changes separately.

Example: “Resume setup” with a manifest and partial issue uses adaptation, ownership receipts and remote-ID reconciliation. Derived corruption uses operations recovery. A README/site alone can use staged cold setup.

For setup or scope expansion, overview/scouting precedes decomposition. Keep sources authoritative, project branding intact and acceptance attributed. Follow existing task authorization.

Handoff outcome, paths/identities, named fractions, coverage, checks, limits and next owner/action. Common mistakes: parallel ledgers, duplicate creates, or reinitializing authored work.
